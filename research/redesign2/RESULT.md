# 새 디자인·데이터 연결 작업 결과

## 완료 범위

사용자가 첨부한 `code.html`, `screen-2.png`를 기준으로 홈의 사진·차콜·골드 구성과 메뉴 흐름을 반영했습니다. 시안에서 사용한 이미지를 로컬 파일로 받아 CDN 없이 표시합니다. 이 이미지는 `DESIGN IMAGE`로 구분하고 실제 매장 사진이라고 표시하지 않습니다.

## 데이터 정리

- GitHub 저장본의 실행 코드에는 검토 정본22곳 외에 CSV 자료87곳이 자동 병합되어109곳이 되던 경로가 있었습니다.
- 자동 병합을 끊고 정본 `research/venues.json`의22곳만 공개 모델로 사용합니다.87곳의 폐업이나 허구성을 개별 확인했다는 뜻이 아닙니다.
- 예전 CSV·중복 사이트 폴더·삭제 대상이 다시 포함된 오래된 inbox 파일을 제거했습니다.
- 기존22곳의 원본 레코드는 작업 전 baseline과 deep-equal 비교에서 변경 없음. 검토일을 새로 확인한 것처럼 갱신하지 않았습니다.
- JSON 단일 원본 → 컴파일 → 공통 읽기 모델 → 화면/API/정적JSON으로 연결했습니다. 외부 MySQL이나 운영자 인증 DB를 새로 구축했다고 주장하지 않습니다.
- Node: `/api/catalog`, `/data/catalog.json`. 정적: `dist/data/catalog.json`.

## 삭제·교정한 미확인 주장

100% 실사/허가 검증, 만족도98.7%, 바가지0건 보장, 현재 영업 레이더,24시간 상담·신고 처리, 이용자 평점·후기, 전국 등록 커버리지, 전 매장 확정 총액·인기순 정렬 문구를 제거했습니다. 정책·업종·검색 화면에 남아 있던 같은 성격의 주장도 교정했습니다.

운영되지 않는 문의·등록·계산 API는410을 반환합니다. 예전 광고·등록·가격 페이지 경로에는 실제 안내문을 보여주며 가상 접수나 가상 예약 성공을 만들지 않습니다.

## 배포 문제 수정

이전 `.github/workflows/deploy.yml`은 `v28-light-menu`와 루트에 남은 옛 HTML만 검사·복사했습니다. 현재 워크플로는 npm 설치 → 데이터 검증 → 로컬 자산 구성 → 현재 소스 정적 빌드 → `dist/` 게시로 바꿨습니다. 이것은 **배포 설정 파일 수정**이며 원격 반영·GitHub Actions 실행을 완료했다는 뜻은 아닙니다.

## 남는 한계

- 현재 영업·허가·안전·가격·예약 가능 여부는 매장에 직접 확인해야 합니다.

- 제공된 시안 이미지의 제작 방식·상업 이용권을 확인 완료했다고 주장하지 않습니다. 외부 공개 전 권리자의 허락을 확인해야 합니다.
- 원격 사이트에 반영하려면 수정 소스와 워크플로를 업로드하고 Pages Source를 GitHub Actions로 설정해야 합니다.
