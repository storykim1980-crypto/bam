# v21 — 방문 없이 운영하는 공개자료 기반 업데이트

## 상태

- 기존 행정자료 기반 걸즈바·마사지 87곳은 이번 상세 조사를 완료한 매장이 아님. 공개 전체 99곳.
- 업주 확인·전화·현장·현재 영업·허가 확인은 모두 미실시. 조사 상세는 noindex 유지.
- 매장 사진은 복사하지 않음. 세 테마의 새 AI 이미지는 업종 공통이며 특정 매장의 재현이 아님.
- 로컬 구현과 정적 산출물만 갱신. GitHub 업로드·외부 배포 미실행.

## 가장 빠른 운영 순서
1. 스낙크 → 걸즈바 → 마사지 순으로 공식 사이트 또는 재사용 조건을 확인한 공개자료에서 개별 사실을 조사한다.
2. 홍보 문장·리뷰·사진을 복사하지 않고 주소, 공개 연락처, 시간, 실제 요금의 조건을 독립적으로 요약한다. 공개 정보라도 약관·데이터베이스 권리·이용 제한은 별도 확인한다. 대량 스크래핑 권한을 가정하지 않는다.
3. `research/venues.json`과 같은 구조의 JSON 배열을 `research/inbox/`에 준비한다. 불명확한 값은 null, 다국어 안내에는 미확인이라고 명시한다. 각 필드에는 fieldSources URL 배열을 기록한다. checkedAt은 사람이 내용을 실제 확인한 날짜이다.
4. `npm run research:import -- research/inbox/파일.json --dry-run`으로 사전 검사한다.
5. `npm run research:import -- research/inbox/파일.json`으로 slug 기준 갱신한다. 게시하려면 status=published_research. draft/archived는 공개 상세 목록에 포함하지 않는다. 업주 동의가 없다는 이유만으로 공개 사실 요약을 막지 않지만, 확인 완료라고 표시하지 않는다.
6. `npm run research:validate && npm run qa:research && npm run research:compile && npm run bundle && npm run build:pages`를 실행한다. 서버는 데이터 변경 후 재시작한다.
7. `npm run research:report`로 30일 초과 재검토 대기 목록을 만든다. 자동 예약 작업이나 무인 사실 판독은 구현하지 않았다. 후속 작업 시 이 목록을 사용한다.

## 보호 장치
- 세 업종 지원, 중복 slug/id/명칭+주소 감지, 주소·언어별 이름·출처·지도·확인일 검증.
- 전화번호 자리표시자, HTTPS 아닌 링크, 직접 로컬 IP/인증정보 포함 링크 차단.
- 온라인 일괄 등록에서 업주·전화·현장·영업·허가 확인 상태를 임의로 부여하지 못함.
- 타 사이트 매장 사진은 이 일괄 경로로 발행할 수 없음. 실제 사진은 별도 권리 검토가 필요함.
- 가져오기 dry-run은 데이터와 공개 모듈을 변경하지 않음. 검증 실패 시 기존 데이터 보존.
- `research:links`는 관리자 로컬 CLI에서만 실행한다. URL의 HTTP 도달성만 검사하며 사실·권리·영업 확인을 대신하지 않고 checkedAt을 바꾸지 않는다. 리다이렉트는 자동 추적하지 않는다. 인터넷 공개 입력용 API나 보안 샌드박스가 아니므로 신뢰하는 출처 URL만 넣는다.
- 날짜 검증은 신뢰한 프로젝트 기준일 2026-11-08과 시스템 UTC 날짜 중 늦은 날짜를 사용한다. 최초 개발환경 시계가 하루 늦어 생긴 오류를 방지한다.
